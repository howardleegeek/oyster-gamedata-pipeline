## 前提条件

開始する前に、以下が揃っていることを確認してください：

- **Git** がインストールされていること
- **Python 3.8+** と pip
- **Docker** と **Docker Compose**（ローカル開発用）
- プロジェクトリポジトリへのアクセス権
- 必要な API キーと認証情報

## クイックスタート

### 1. リポジトリをクローン
```bash
git clone https://github.com/your-org/session-recorder.git
cd session-recorder
```

### 2. 環境設定
```bash
cp .env.example .env
# 認証情報で .env を編集
```

### 3. 依存関係をインストール
```bash
pip install -r requirements.txt
```

### 4. サービスを起動
```bash
docker-compose up -d
```

### 5. レコーダーを実行
```bash
python -m recorder.cli start --session-id my-first-session
```

## コアコンセプト

### セッション
**セッション**は、一意の識別子を持つ単一の記録インスタンスを表します。セッションはユーザーインタラクション、システムイベント、メタデータをキャプチャします。

### 標準パイプライン
**標準パイプライン**は、生のセッションデータを完全なプロベナンス情報を持つ監査可能な記録に変換する標準的な処理ワークフローです。

### 監査
**監査**は、セッション記録のコンプライアンスと品質保証のためのレビューおよび検証プロセスを指します。

### プロベナンス
**プロベナンス**は、生の記録から最終的な監査報告書までのデータ変換の完全な系譜を追跡します。

### ウォッチドッグ
**ウォッチドッグ**は、システムの健全性を確保し、異常時にアラートを発する監視デーモンです。

### ルートタイプ
**ルートタイプ**は、記録されたセッション内のユーザーナビゲーションパスの分類を定義します。

### 再生
**再生**は、画面キャプチャ、ユーザーインタラクション、システムイベントを含む完全な忠実度で記録されたセッションをレビューすることができます。

## セッション記録

### 記録の開始
```bash
python -m recorder.cli start \
  --session-id "user-123-session" \
  --output-dir ./sessions \
  --metadata '{"user_id": 123, "environment": "production"}'
```

### 記録設定
`recorder_config.yaml` を作成：
```yaml
session:
  max_duration: 3600  # 秒
  compression: gzip
  encryption: true
  
capture:
  screen: true
  audio: false
  network: true
  system_events: true
  
storage:
  backend: s3
  bucket: session-recordings
  region: us-east-1
```

### セッションメタデータ
各セッションには以下が含まれます：
- **session_id**：一意の識別子
- **start_time**：ISO 8601 タイムスタンプ
- **user_context**：ユーザー情報
- **environment**：本番/ステージング/開発環境
- **route_type**：初期ナビゲーション分類

## 監査パイプライン

### パイプライン段階
1. **取り込み**：生のセッションデータの受信
2. **検証**：データ整合性チェック
3. **変換**：正規化とエンリッチメント
4. **分析**：パターン検出と異常スコアリング
5. **報告**：監査報告書の生成

### パイプラインの実行
```bash
python -m pipeline.process \
  --session-id "user-123-session" \
  --pipeline canonical \
  --output-format json
```

### 監査報告書
監査報告書には以下が含まれます：
- セッション完全性スコア
- データ整合性検証
- 異常検出結果
- プロベナンスチェーンの検証
- コンプライアンスチェックリスト

## ダッシュボードの使用

### ログイン
ダッシュボードにアクセス：`http://localhost:8080`

1. **ログイン**をクリックして認証情報を入力
2. OAuth 2.0 で認証
3. 組織を選択

### セッション管理
- **セッションを表示**：すべての記録セッションを閲覧
- **ルートタイプでフィルター**：ナビゲーションタイプでセッションをフィルター
- **検索**：ID またはメタデータでセッションを検索
- **エクスポート**：様々な形式でセッションデータをダウンロード
- **再生**：完全な再生機能で記録されたセッションをレビュー

### 監査インターフェース
- **承認**：セッションをコンプライアンスとしてマーク
- **拒否**：レビューが必要なセッションをフラグ付け
- **コメント**：監査ノートを追加
- **支払い保留中**：処理待ちのセッション

### ウォッチドッグステータス
システムの健全性を監視：
- **アクティブセッション**：現在記録中
- **パイプラインスループット**：1時間あたりの処理セッション数
- **エラーレート**：記録失敗の割合
- **ストレージ使用量**：ディスク/S3 使用率

## トラブルシューティング

### 一般的な問題

#### "レコーダーを起動できません"
```bash
# ポートが利用可能か確認
netstat -an | grep 8080

# Docker が実行中か確認
docker ps
```

#### "セッションデータが破損しています"
```bash
# データ検証を実行
python -m recorder.validate --session-id problematic-session

# ストレージバックエンドを確認
aws s3 ls s3://session-recordings/
```

#### "ダッシュボードログインに失敗します"
1. localhost のブラウザクッキーをクリア
2. `.env` の OAuth 認証情報を確認
3. バックエンドサービスのログを確認：
```bash
docker-compose logs auth-service
```
