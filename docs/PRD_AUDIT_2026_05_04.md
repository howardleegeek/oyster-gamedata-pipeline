## Field schema (canonical, from PRD pages 4-5)

### `systeminfo.json` (file 1)
```json
{
  "gameProcessName": "ds",
  "x": 64, "y": 255,
  "width": 2560, "height": 1600,
  "recordDpi": 1.5
}
```

### `action_camera.json` (file 2) — 20 fields per record, 30fps
```
time:                       string MM-DD H...
fps:                        float (current game fps)
frame:                      int (frame index)
route_type:                 int (1=normal, 2=special, 3=loop)
camera_position:            Vector3 [m, left-hand]
camera_rotation_oula:       Vector3 (Euler degrees, [-180,180])
camera_rotation_quaternion: Vector4 [x, y, z, w] order
camera_Follow Offset:       Vector3 [m]   ← yes, with space and capital F
camera_intrinsics:          Object {fx, fy, Cx, Cy}  ← capital Cx Cy, fx==fy
camera_speed:               Vector3 [m/s]
player_position:            Vector3 [m, left-hand]
player_rotation_oula:       Vector3
player_rotation_quaternion: Vector4 [x, y, z, w]
player_speed:               Vector3 [m/s]
mouse_x:                    float (normalized [0,1])
mouse_y:                    float (normalized [0,1])
mouse_dx:                   float (normalized delta)
mouse_dy:                   float (normalized delta)
keyCode:                    int (single ASCII / VK code)
metric_scale:               float (game world to physical world ratio)
```

### Coordinate system
**Left-handed**: right=+x, up=+y, front=+z. Angles in degrees [-180, 180].
- Pitch: around X axis, z-axis = 0°, head-up + / head-down -
- Yaw: around Y axis, x-axis = 0°, left -/right +
- Roll: around Z axis, y-axis = 0°, left tilt -/right tilt +

### Recording requirements (from p8)
- Video resolution: **1920×1080**
- Frame rate: **30fps** strict
- Clip duration: **5-6 min** per clip
- Per scene: **≤30 min, ≤240 clips, ≤20 hours** per vendor per game
- Network latency during capture: **<20ms**
- Audio: continuous, clear, no noise, no distortion, even volume, sync with video
- Mouse: 1800 dpi, system pointer speed 6 (Win10) / 10 (Win11)
- Hardware: i5-12400F / Ryzen 5 5600 minimum, 16GB+ RAM, 1080p needs 3060+ GPU

### What MUST NOT appear in video (hard rejection criteria, p8)
- UI overlay (must be force-disabled in-game)
- More than 2 other characters/animals besides player
- Scene splicing
- View-angle switching (1st↔3rd person)
- Game logo
- Lag / frame drops
- Popups, system notifications, watermarks
- Modal dialogs, save-dialog, "press key to continue"
- Loading screens, CG cinematics, plot scenes
- In-game settings UI
- Pop-up secondary interactions
- Switching out of game (Alt-Tab, desktop reveal)
- Black bars, mosaics
- Fast cuts, jitter, over-bright, over-dark
- Frequent costume / mount switching

### What MUST appear (p9 — required behavior)
- Primary action: environmental exploration
- Diverse motion variety
- Action → screen causal clarity (e.g., "left turn → screen moves left")
- Walk + run + camera-look = >90% of action time
- Allowed: jump, climb-near-walls, special-route extreme angles
- Required time-management: 25-second pre-loop / mid-traverse / 10s closing-loop for `route_type=3`

### Acceptance protocol (p7)
1. **Per-scene JSON validation**: 2 random samples; if both fail → entire scene rejected.
2. **Per-scene video validation**: 2-5% random sample; <90% pass → entire scene rejected.
3. **90-99% pass**: vendor must backfill the missing percent (e.g. 95% pass on 120 → fill 6 more clips).

### JSON validation specifics (p11)
1. Field presence + format
2. Coordinate alignment: camera + player location/rotation match PRD's left-hand convention
3. Input mapping correctness: dx/dy direction matches actual camera motion
4. Frame continuity: no duplicate or skip
5. keyCode timing: matches screen action; ASCII per spec (W=87)
6. Quaternion order: `[x, y, z, w]`
7. Speed magnitudes: physically reasonable
8. **camera_intrinsics: fx == fy** (square pixels)
