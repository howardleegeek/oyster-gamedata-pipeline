# Lint v3 Fuzz Bug Report — 2026-05-13

**Target:** `bin/lint_v3_prd_grounded.py`
**Branch:** `qa/fuzz-lint-runner`
**Worktree:** `/tmp/wt-fuzz-lint`
**Base SHA:** `6f78baf2b132d34a37fe0363de48fc326894d571`
**Mode:** Continuous adversarial fuzz testing, hypothesis-driven
**Scenarios run:** 30 adversarial directory fixtures + 1 explicit FIFO repro
**Findings:** 20 (5 critical, 10 medium, 5 minor)

## Methodology

The lint runner accepts a **directory** (the unpacked 5-file delivery), not a tarball. The tarball is extracted by the buyer/CI before lint runs. So we fuzz at the directory level: 30 hand-crafted adversarial directories were generated by `/tmp/fuzz_run.py`, each varying one or more attack vectors (malformed video, NaN floats, wrong quaternion order, FIFOs, etc). Output reports were captured to `/tmp/fuzz-dirs/<scenario>.out.json` and analyzed.

A reference "valid" baseline (`/tmp/ref-extract`, from `samples/buyer-spec-v1-rc1.tar.gz`) was the control. **Even the reference fails 2/24 checks (depth criteria 15 + 16)** — see Finding M-10.

Every finding below lists:
- **Severity:** 🔴 critical (false-pass/crash/DoS) · 🟡 medium (false-fail or weak detection) · 🟢 minor (UX/cosmetic)
- **Criterion ID** in lint v3 affected
- **Reproducer command** (deterministic, works on macOS)
- **Actual vs expected** behavior
- **Suggested fix sketch** (one or two lines, not full code)

## 🔴 Critical Findings (must-fix before vendor onboarding)

### C-01: 0-byte `video.mp4` passes all 24 checks
- **Criterion(s):** 1, 2, 3, 4 (Video Resolution, Duration, FPS, Format)
- **Severity:** 🔴 critical — silent acceptance of completely invalid data
- **Reproducer:**
  ```bash
  mkdir -p /tmp/repro_C01/depth
  : > /tmp/repro_C01/video.mp4                    # zero-byte mp4
  echo '{"gameProcessName":"x","x":0,"y":0,"width":1920,"height":1080,"recordDpi":1,"map_scale":1,"map_bounds":{"min_x":-1,"min_z":-1,"max_x":1,"max_z":1}}' > /tmp/repro_C01/systeminfo.json
  echo '[{"frame":0,"fps":30,"keyCode":[87],"camera_intrinsics":{"fx":960,"fy":960}}]' > /tmp/repro_C01/action_camera.json
  : > /tmp/repro_C01/gameinfo.xlsx
  python3 -c "import OpenEXR,Imath,numpy as np; h=OpenEXR.Header(1920,1080); h['channels']={'Z':Imath.Channel(Imath.PixelType(Imath.PixelType.FLOAT))}; o=OpenEXR.OutputFile('/tmp/repro_C01/depth/depth_000000.exr',h); o.writePixels({'Z':np.full((1080,1920),5,dtype=np.float32).tobytes()}); o.close()"
  python3 bin/lint_v3_prd_grounded.py /tmp/repro_C01
  ```
- **Actual:** `Passed: 24/24, Failed: 0`. Video checks report `"1920x1080 required"` and `"5-6 min required"` as PASS messages — but those strings are tautologies, not actual measurements.
- **Expected:** Video file must be opened, dimensions read (e.g. via `ffprobe`/PyAV), duration measured. A 0-byte file should fail criteria 1, 2, 3.
- **Fix sketch:** In `_check_video_specs`, parse each `.mp4` with `ffprobe -v error -show_streams -of json`, assert resolution = 1920x1080 and duration in [300, 360] sec. Stop using `bool(vids)` as a stand-in for "passed".

### C-02: Linter hangs indefinitely on FIFO/named-pipe in `depth/`
- **Criterion(s):** 15, 16 (Depth Invalid-Pixel Ratio, Depth Data Quality)
- **Severity:** 🔴 critical — DoS / availability bug; one malicious vendor submission halts the buyer's lint queue
- **Reproducer:**
  ```bash
  # See /tmp/repro_fifo.py — abbreviated:
  mkdir -p /tmp/repro_C02/depth
  # ... populate the other 4 required files ...
  mkfifo /tmp/repro_C02/depth/depth_000000.exr
  timeout 10 python3 bin/lint_v3_prd_grounded.py /tmp/repro_C02
  echo "exit=$?"   # 124 (timeout), elapsed > 10s
  ```
- **Actual:** `OpenEXR.InputFile(str(df))` blocks reading from the FIFO. Process must be killed externally. Confirmed in run: 60s timeout exhausted.
- **Expected:** Skip non-regular files (`if not df.is_file()` or `S_ISREG(stat.st_mode)`) before opening. Or set a per-file read timeout.
- **Fix sketch:** Add `if not df.is_file() or df.is_symlink(): issues.append((df.name, "not a regular file")); continue` at the top of the EXR loop.

### C-03: Quaternion criterion 13-14 only checks `len == 4`, never axis order or unit-norm
- **Criterion(s):** 13 (Quaternion xyzw Order), 14 (Quaternion Normalization)
- **Severity:** 🔴 critical — silent acceptance of wrong-order quaternions causes catastrophic geometry errors in downstream world-model training
- **Reproducer:**
  ```bash
  mkdir -p /tmp/repro_C03/depth
  # ... 5 required files ...
  echo '{"quaternion":[1.0,0.0,0.0,0.0]}' > /tmp/repro_C03/quat_top.json   # identity in [w,x,y,z]
  python3 bin/lint_v3_prd_grounded.py /tmp/repro_C03 | grep -i quat
  ```
- **Actual:** `Quaternion xyzw Order: All quaternions valid`, `Quaternion Normalization: Quaternion normalization check passed`. Linter only verifies `isinstance(q, list) and len(q) == 4` — it cannot distinguish `[w,x,y,z]` from `[x,y,z,w]` from `[junk,junk,junk,junk]`.
- **Expected:** PRD requires xyzw order. Heuristic: read all quaternions over an episode, check that the **last** element is dominant for ≥85% of frames (consistent with identity-rotation rest poses being `[0,0,0,1]`); check `‖q‖ ∈ [0.99, 1.01]`.
- **Fix sketch:** Load each quaternion, compute `np.linalg.norm(q)` (should be 1.0±0.01) and `abs(q[3]) > abs(q[i]) for i in 0..2` for ≥85% of records. Currently neither check exists.

### C-04: `keyCode` integer check accepts booleans (`True`/`False`) as valid keyCodes
- **Criterion(s):** 17 (keyCode Integer Format), 18 (KeyCode Validation)
- **Severity:** 🔴 critical — `isinstance(True, int)` is True in Python; bool fields slip through silently and corrupt downstream input-event parsing
- **Reproducer:**
  ```bash
  mkdir -p /tmp/repro_C04/depth
  # ... 5 required files ...
  echo '{"keyCode": true}' > /tmp/repro_C04/actions_bool.json
  python3 bin/lint_v3_prd_grounded.py /tmp/repro_C04 | grep -i keycode
  ```
- **Actual:** Both criterion 17 and 18 PASS. `True` is treated as `1`.
- **Expected:** Reject booleans explicitly. Valid keyCode is a non-negative integer in `[0, 0xFF]` (Windows VK_*).
- **Fix sketch:** Replace `not isinstance(data["keyCode"], int)` with `(isinstance(data["keyCode"], bool) or not isinstance(data["keyCode"], int) or data["keyCode"] < 0 or data["keyCode"] > 255)`.

### C-05: `keyCode` check only inspects **top-level** field in JSON; misses the entire `action_camera.json` records list
- **Criterion(s):** 17, 18
- **Severity:** 🔴 critical — the **canonical 5-file delivery's** `action_camera.json` is a `List[Dict]`. The linter does `if isinstance(data, dict) and "keyCode" in data` — for a top-level list, `isinstance(data, dict)` is False, so **all 9000 records are skipped**. Every record's keyCode could be a string and pass.
- **Reproducer:**
  ```bash
  mkdir -p /tmp/repro_C05/depth
  # baseline ...
  # action_camera.json with ALL string keyCodes:
  python3 -c "import json; json.dump([{'frame':i,'fps':30,'keyCode':'STRING_NOT_INT','camera_intrinsics':{'fx':960,'fy':960}} for i in range(100)], open('/tmp/repro_C05/action_camera.json','w'))"
  python3 bin/lint_v3_prd_grounded.py /tmp/repro_C05 | grep -i keycode
  ```
- **Actual:** Both PASS.
- **Expected:** Iterate records: `data if isinstance(data, list) else [data]`, then check each `rec["keyCode"]`.
- **Fix sketch:** In `_check_keycode`, after `data = json.load(f)`, normalize: `records = data if isinstance(data, list) else [data]`, then walk records.

## 🟡 Medium Findings

### M-01: `fx == fy` check skips `action_camera.json` entirely
- **Criterion:** 12 (Camera Intrinsics fx==fy)
- **Severity:** 🟡 medium — same root cause as C-05: linter only globs `**/*intrinsics*.yaml` and `**/*camera*.yaml`. The actual delivery format has `camera_intrinsics: {fx, fy, cx, cy}` per record in `action_camera.json`. So fx ≠ fy throughout the recording goes undetected.
- **Reproducer:**
  ```bash
  mkdir -p /tmp/repro_M01/depth
  # baseline ...
  python3 -c "import json; json.dump([{'frame':0,'fps':30,'keyCode':[87],'camera_intrinsics':{'fx':1.0,'fy':1000000.0}}], open('/tmp/repro_M01/action_camera.json','w'))"
  python3 bin/lint_v3_prd_grounded.py /tmp/repro_M01 | grep -i intrinsics
  ```
- **Actual:** `Camera Intrinsics fx==fy: All fx==fy`. False pass.
- **Expected:** Open `action_camera.json`, walk records, assert `abs(fx - fy) / max(fx, fy) < 0.001`.
- **Fix sketch:** In `_check_intrinsics`, add a dedicated branch for `action_camera.json`: iterate the list of records and extract `camera_intrinsics`.

### M-02: NaN / Inf in any numeric field is never detected
- **Criterion:** 12, 13, 14 (numeric integrity in general — no dedicated criterion)
- **Severity:** 🟡 medium — a recording with `fx = Infinity` or `fps = NaN` is silently accepted; downstream training will produce NaN gradients
- **Reproducer:**
  ```bash
  mkdir -p /tmp/repro_M02/depth
  # baseline ...
  python3 -c "import json; json.dump([{'frame':-1,'fps':float('nan'),'keyCode':[87],'camera_intrinsics':{'fx':float('inf'),'fy':float('inf')}}], open('/tmp/repro_M02/action_camera.json','w'))"
  python3 bin/lint_v3_prd_grounded.py /tmp/repro_M02
  ```
- **Actual:** 24/24 PASS. (Side note: Python's default `json.dumps` *does* serialize NaN/Infinity, which is technically invalid JSON RFC 8259 but most parsers accept it.)
- **Expected:** Walk all numeric fields in `action_camera.json`, assert `math.isfinite(v)`.
- **Fix sketch:** Add a new criterion (e.g., 25 "Numeric Integrity") that recurses through every `dict` and `list`, asserting `isinstance(v, (int, float)) → math.isfinite(v) and not isinstance(v, bool)`.

- **Expected:** Also assert `data.get(fld) not in (None, "", [])`.

### M-04: Negative frame numbers silently accepted
- **Criterion:** 18 (KeyCode Validation — generic record validity)
- **Severity:** 🟡 medium — `frame: -1` is nonsensical (frames are 0-indexed monotonic). Linter never inspects `frame` field.
- **Reproducer:**
  ```bash
  mkdir -p /tmp/repro_M04/depth
  # baseline with action_camera containing frame=-1:
  echo '[{"frame":-1,"fps":30,"keyCode":[87],"camera_intrinsics":{"fx":960,"fy":960}}]' > /tmp/repro_M04/action_camera.json
  ```

- **Expected:** Assert frames are monotonic non-negative integers starting at 0.
- **Fix sketch:** Add criterion 26 "Frame Monotonicity": `frames = [r["frame"] for r in records]; assert frames == sorted(frames) and frames[0] == 0`.

### M-05: `systeminfo.json` injection content (SQLi, XSS payload) silently passes
- **Criterion:** (no criterion verifies content integrity of `systeminfo.json`)
- **Severity:** 🟡 medium — `gameProcessName: '"; DROP TABLE tarballs; --'` is accepted. If buyer pipelines later interpolate this into SQL or shell, this is exploitable.
- **Reproducer:**
  ```bash
  mkdir -p /tmp/repro_M05/depth
  echo '{"gameProcessName":"\"; DROP TABLE tarballs; --","x":0,"y":0,"width":1920,"height":1080,"recordDpi":1,"map_scale":1,"map_bounds":{"min_x":-1,"min_z":-1,"max_x":1,"max_z":1},"session_id":"<script>alert(1)</script>"}' > /tmp/repro_M05/systeminfo.json
  # ... rest of baseline ...
  python3 bin/lint_v3_prd_grounded.py /tmp/repro_M05
  ```
- **Actual:** 24/24 PASS.
- **Expected:** Validate `gameProcessName` against allow-listed regex `^[A-Za-z0-9._-]+\.(exe|app)$`. Validate session_id matches `^[A-Za-z0-9_-]{8,64}$`.
- **Fix sketch:** Add criterion 27 "Systeminfo Schema Validation" with regex on each string field.

### M-06: Linter follows symlinks blindly — possible info leak
- **Criterion:** 15, 16, 23
- **Severity:** 🟡 medium — `depth/depth_evil.exr -> /etc/passwd` is opened by `OpenEXR.InputFile`. While OpenEXR will reject non-EXR data, the linter still performs a `stat`+`open` on the symlink target. Combined with logging, this could leak file existence (and content if a later check uses `Image.open` / `np.load` for non-symlink-aware reads). Also a subtle TOCTOU vector during CI.
- **Reproducer:**
  ```bash
  mkdir -p /tmp/repro_M06/depth
  # baseline ...
  ln -s /etc/passwd /tmp/repro_M06/depth/depth_evil.exr
  python3 bin/lint_v3_prd_grounded.py /tmp/repro_M06 -v
  ```
- **Actual:** Symlink is opened and read. Linter reports `read-err: TypeError` or similar.
- **Expected:** Skip symlinks: `if df.is_symlink(): continue` or follow only after checking the target is within `data_dir`.
- **Fix sketch:** Guard all file opens with `if df.is_symlink(): continue`. Same in `_check_image_specs` (which calls `Image.open`).

### M-07: Criterion 24 (Directory Structure) is **case-sensitive** on the `depth/` directory but uppercase variants of `video.MP4` are missed for the directory check while still failing the format/glob check inconsistently
- **Criterion:** 24
- **Severity:** 🟡 medium — gives confusing UX: `Depth/` capitalized fails one check but `*.MP4` (uppercase ext) escapes from the video-glob entirely (which is case-sensitive in glob), creating inconsistent error messages
- **Reproducer:**
  ```bash
  mkdir -p /tmp/repro_M07/Depth   # capital D
  # ...same baseline but Depth/ dir...
  python3 bin/lint_v3_prd_grounded.py /tmp/repro_M07
  ```
- **Actual:** Criterion 24 fails for `Depth` (capital), but depth/EXR files (criteria 15/16) are sometimes reported as "No depth files" — inconsistent message.
- **Expected:** Decide one of (a) strict case-sensitive matching with a clear error, or (b) case-insensitive matching everywhere. Document the choice.
- **Fix sketch:** Normalize to lowercase: `existing_dirs = {x.name.lower() for x in d.iterdir() if x.is_dir()}` — then choose semantic strictness explicitly.

### M-08: Single-record `action_camera.json` (dict instead of list) misclassified
- **Criterion:** 17, 18
- **Severity:** 🟡 medium — when `action_camera.json` is mistakenly a single dict, the linter picks up `keyCode: [87]` (a list) at the dict's top level. Since `[87]` is a list, not int, criterion 17 fails — but the error message says `"1 non-int"` which is misleading. The actual bug (wrong shape) is masked as a value error.
- **Reproducer:**
  ```bash
  mkdir -p /tmp/repro_M08/depth
  echo '{"frame":0,"fps":30,"keyCode":[87],"camera_intrinsics":{"fx":960,"fy":960}}' > /tmp/repro_M08/action_camera.json
  ```

- **Actual:** `keyCode Integer Format: 1 non-int`. Misleading: caller will think keyCode value is wrong, not the file shape.
- **Expected:** Detect schema mismatch first: `if action_camera.json top-level is not a list: fail with "expected JSON array of records, got dict"`.
- **Fix sketch:** Add an early schema-shape check for `action_camera.json` specifically before keyCode validation runs.

- **Criterion:** Multiple (any criterion that opens JSON)

### M-10: Reference sample (the **valid** baseline shipped in `samples/`) fails depth criterion 15
- **Criterion:** 15, 16
- **Severity:** 🟡 medium — the shipped "known-good" sample fails the linter; this means either the sample is broken or the linter's threshold is wrong. Either way, vendors cannot use this sample as ground truth.
- **Reproducer:**

## Closing observations
